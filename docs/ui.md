# UI design language

Scope: the tray flyout, the settings window, the PIN and password dialogs, the tray icon, and their motion. This page is the design contract for anyone adding or changing UI: which tokens and widgets to use, how things move, what the states look like, and how a change is verified without a human.

The values live in code, not here. `theme.go` owns the palette, `ui_kit.go` owns the shared widgets and motion primitives, `flyout.go` owns the content geometry and `window_scale.go` the window sizing — the tests named below pin them. This page carries the rules and the inventory; when code and this page disagree, code wins and this page is updated in the same commit.

Sources: `mygo-cloudmusic` for native UI structure and style; Tuneblade for the device-list, volume, and connection-status layout (reference only, never code); magpie for the flyout and settings-window look (reference its look, never its code). The codebase-orientation side of the UI — which files, which windows — is in [implementation.md](implementation.md).

## Tokens and widgets

- Every color comes from the `palette` struct in `theme.go`, which maps the platform theme onto the design's light and dark palettes (`bg`, `panel`, `card`, `pill`, `line`, `fg`, `muted`, `accent`, `sel`, `green`, `red` families). The platform theme is Windows' appearance unless 通用 → 外观 pins 浅色 or 深色; that choice is saved as `theme` in `settings.json` and applied through `mygo.Theme.SetSource` before the first window paints. Never hardcode a color; never branch on dark mode outside `theme.go`.
- Text scale and high contrast follow the desktop. Each window carries the text scale as a content zoom set in `design` (`theme.go`), clamped to 0.5–3.0 (0, or no platform setting, means 1), so the design's DIPs stay exact and the layout does not clip; `window_scale.go` adds the scale around the content when it sizes and shows a window. High contrast strengthens the palette's hairlines and secondary text (`palette.withPreferences`), and the stock widgets' theme follows the same setting.
- Every repeated control comes from `ui_kit.go`: `sectionHead` (the flyout section header, with an optional spinner and trailing action), `iconButton`, `rowAction` (a 26-DIP row action; without a handler it is a status and takes no focus), `chipButton` (the 28-DIP field commit), `cardAction` (the 30-DIP card action), `linkButton` (the 30-DIP text action), `primaryButton` and `quietButton` (the 34-DIP dialog actions), `chip` (the 22-DIP status chip in neutral/OK/accent/danger), `inlineChip` (the 20-DIP name chip), `countBadge` (the 18-DIP group count), `cardHead` (a page card header with a fixed 22-DIP leading tile), `segmented` (the 30-DIP segmented control), `emptyCopy` (an empty state's title and hint), `infoNote` (a muted caveat with an info glyph that wraps), `toggle`, `slider`, `settingRow` (and `settingRowColors` for the greyed hidden group), `rowLine`, `fieldInput`, `fieldSelect`, `staticText`. Do not rebuild these inline. The action ladder is 26 row, 28 field commit, 30 card, 34 dialog. A row is 56 DIP high with a 13/500 title and an 11.5 subtitle. The type scale is 8.5, 10.5, 11.5, 12.5, 13, 15, 18.
- A caveat about something outside the card (the audio device, the receiver, a HomePod setting) sits under the card as `infoNote`: an info glyph in a 16-DIP slot and 11.5 px muted copy. An interaction hint or a description stays inside the card as plain secondary text, without the glyph. The caveat names the control or setting it concerns.
- A page card header uses `cardHead`: a fixed 22-DIP leading tile, a 13/600 title, and a trailing cluster in a 44-DIP row. The 正在播放, 音频, and 氛围灯 cards align their titles at 44 DIP. The update S1 status card keeps its 34-DIP tile and is the one documented exception.
- Card radii are surface-specific: flyout cards 10 (the media card nested in the playback card is 12), settings cards 12, dialogs 14. Inner tiles are 6, 8, 9, 10, or 14 by size.
- One `phase` — idle, connecting, streaming, error — derives from the engine's finer-grained sender states (`phaseOf`) and drives the whole interface's color (`phaseColor`). `face` adds one distinction inside streaming: a stream with no audible audio shows the resting face. New UI speaks in phases, not in sender states.

## Motion

Rules:

- Durations use four tiers only: 140 ms selection/switch, 150 ms dialog panel, 160 ms page/content, 180 ms entrance. Nothing over 240 ms except loading indicators.
- Default curve `EaseOut`; symmetric in/out pairs use `EaseInOut`; never `Bouncy`; never the default `Smooth`/`Snappy` (500 ms — too slow for this design) without an explicit short `Duration`.
- Window and page content switches run through `Transition` at 160 ms; `ContentTransition` is not used.
- Reduce Motion (the system setting) degrades automatically: poses land directly while fades stay, `Transition` lands directly while colors stay smooth, `Timeline` jumps to the end. `Loop` keeps running but is used only for loading and searching, never decoration.
- Animation keys are stable identities — the device ID for a device row, the section ID for a settings page, `"on"`, `"lamp-open"`, `"pulse"` — never an index.
- No business state changes inside animation callbacks; observe with `Settled`/`Arrived`/`Transitioning` instead.
- The first frame shows the final state. Only an explicit entrance or a user action starts an animation; `enterPose` and `dialogPose` run once per show through an entered flag.

Motion tokens:

| Token | API | Value | Reduce Motion |
|---|---|---|---|
| select | `Transition` (Colors) | 140 ms, EaseOut | colors keep |
| content / page | `Transition` | 160 ms, EaseOut | fade only |
| dialog pose | `AnimatePose` | 150 ms, EaseOut | fade only |
| enter | `AnimatePose` / `Transition` | 180 ms, EaseOut | fade only |
| switch / slider / toast | mygo built-ins | 140 / 150 / 200 ms | built-ins comply |
| pulse (loading) | `Loop` | 1.2 s, EaseInOut | keeps running |

Interaction inventory (what moves, and how):

| Interaction | Animation |
|---|---|
| Flyout and settings content entrance | rise 6 points + fade, 180 ms, once per show (`enterPose`) |
| Dialog panel | scale from 98% + fade, 150 ms (`dialogPose`) |
| Device row hover | background color, 140 ms (one transition shared with selection) |
| Device row selection | background `#ECEBFB`, dark `#33345A`, 140 ms |
| Device add/remove/order | none — rows keyed by device ID land in one frame |
| Latency preset segment or tile | selected color lands at once; the click updates the ALAC line at once, the restart waits 300 ms for the last click, and the hold keeps the streaming faces for up to 3 s while a spinner follows the 播放 label |
| Custom latency slider | built-in 150 ms; the restart waits 500 ms after the last change |
| Latency panel switch | switch 140 ms; the flyout height changes by 44 DIP |
| Row-tail action/status swap | none — the swap lands in one frame |
| Now Playing card | updates in place; only the meter animates, 30 fps while the session plays, in the flyout and in the settings preview (the sample preview stays still) |
| Settings page switch | slide 6 px + fade, 160 ms, keyed by section |
| Sidebar active pill | color 140 ms; a static pill, no sliding indicator |
| Input focus ring | none — the keyboard focus ring never fades in |
| Empty/searching state | pulse loop 1.2 s on the search face, opacity 0.55–1 |
| Tray icon | 12 frames at 100 ms while connecting or streaming; the static face otherwise |
| Tray menu, window show/hide | none — native Windows and mygo own them |

Implementation notes: smoothing the selection color needs a custom row column, because `ui.List`'s built-in selection snaps. Stable keys are what let `Transition` recognize a row across reorder. `Collapse` folds height inside a column. `AnimatePose` and `Transition` complete in paint-only frames on a steady flyout, so the resident window does not rebuild its view every frame.

## Windows and geometry

- The flyout is a frameless, shadowed 420-DIP-wide panel with a 12-DIP window radius, anchored to the tray icon by its bottom edge 6 DIP above the icon. Its height adapts to the device count and the media state: the height constant is 438 (it still subtracts the retired 62-DIP Now Playing row), three device rows at 66 each, a 141 empty state (`flyoutHeightFor` in `flyout.go`), and no flexible spacer, so the playback card follows the device card directly. The device card shows at most three rows and scrolls inside itself past three, so a fourth receiver does not grow the window. Every device row is 66 DIP high, connected or not. A member's row is a compact mixer: a 26-DIP channel icon button before the name, the name beside it, and under them that target's volume slider and percent; the button and the speaker share one 26-DIP lead, so the name and the rail start on one x. The speaker is a button too: one click takes that target's volume to zero and shows the muted speaker, and the next restores the level it muted from. The volume and channel controls belong to a target in the user's session: a member keeps its mixer while the cohort re-establishes, so adding a device never takes the first device's controls away (standby included). A target that is joining, reopening, or failed is plain; a joining row's second line reads 正在连接…, a reopening one reads 正在重连…, and a failed one keeps its model and address, so nothing offers volume before playback. The row's action comes from the target's published state, not the session phase: the engine publishes a `TargetState` for every active target (member, joining, reopening, failed), the row the user's connect started or added is joining and offers 取消, every other session target is a member and offers 断开连接, a wanted target an automatic retry is opening is reopening and also offers 断开连接, and once retries stop it is failed and offers 重试. A rebuild (a target disconnected, a latency change, an automatic retry) names no joiner, so it offers no 取消; canceling the joining row removes just that target. The connect action owns a trailing column, vertically centered in the row, and both line columns end before it. That column is a fixed 92 DIP whatever its label says (取消, 连接, 断开连接, 重新连接), so the name, slider, and percent never move between phases. A row's 断开连接 removes only that target; the device section head carries a 全部断开 action while a session is live, which ends the whole session; the head reserves that action's 10-DIP height in every state, so starting or ending a session never moves the panel. A row without a target keeps the same 26/2/20 line rhythm for its name and model, centered in the same 66. The Now Playing media card adds its own 150 DIP while a session exists and is absent otherwise, so the panel shrinks when playback stops; the latency switch adds 44 DIP, and when neither is present the playback section is left out and the window drops its head, borders, and gap (33 DIP). Three device rows with a media session and the latency row make 660, and with only the latency row 510 (570 and 420 before the permanent ambient section below). A session notice sits under the device card when a member leaves while the rest continue, or while a second target is joining: 44 DIP high and the width of the card, accent for the loss with 重试 and a dismiss, neutral for the join with a dismiss only. It clears on the next user action or after 8 s, and the window adds 52 DIP while it shows. A connection error uses the same 44-DIP bar family with the alert glyph and the red tone; it adds 52 DIP with the body gap. A receiver that refuses its saved password stops the reconnect ladder: the same password dialog reopens for it and a password-rejected error sits under the card while the other targets keep playing. When the saved pairing data could not be read, a credential-recovery bar sits under the device card, below the error bar when both show, with the same text inset and height; its trailing chevron opens a 380-DIP dialog with the reason, the re-pair step, the receiver-reset fallback, and 不再提示 / 重新配对. The bar adds 52 DIP and the dialog is an overlay, so the flyout grows once for the notice and not for the dialog. The ambient section is permanent: 90 DIP collapsed, its head with the 26-DIP power action and a 44-DIP row that carries the 30-DIP priority segment; in template priority, expanding it adds the six-template grid (`flyoutHeightForState`), 53 DIP for one 10-column row, and never more than four rows — past that the grid scrolls inside the card and the window stops growing. Cover priority has no grid. A resize grows upward and leaves the playback card in place.
- The playback card stacks the media card and the latency row in that order; with neither, the section is not drawn. The Now Playing media card names the selected SMTC session in its head with the session-switch arrow; the card follows the system's current session, and the arrow pins another one until a different session becomes current. It then lays out a 52-DIP-tall poster on the left whose width follows the cover's aspect ratio — a 16:9 thumbnail gets a wider poster, never a taller card — the title and artist beside it, and a five-bar meter at the title row's far right. The progress row runs full width: enabled transport controls first, as bare 12-DIP glyphs in the foreground color on 24-DIP hit areas, 2 DIP apart, starting on the card's content column; only the hovered button draws its 24-DIP circle; then elapsed, the cover-field fill and thumb, and remaining. A session without a duration keeps the same row as an empty track, with no fill, thumb, times, or copy. With no session at all the card keeps the latency row; with neither a session nor the latency row the section disappears and `fitFlyout` shrinks the window by its head, borders, and the body gap. The four latency segments lead-align their 14-DIP mode glyphs with an 8-DIP inner inset. Progress fill and meter sample a 23×24 blurred, lightness-compressed field of the cover, so the card follows the art's colors on both themes. The meter gates band energy below -50 dBFS, stops each band's gain 18 dB above that floor, and ignores changes under about a third of a DIP, so dither and room tone leave the bars steady while quiet passages stay low instead of filling them. An unknown app reads 未知应用. The placeholder tile sits on the raised card surface, like the session-switch button, so it reads as a cover distinct from the media card's pill; the artwork's own tile keeps the pill, so a corner sliver never shows as a light edge. The 封面 setting elects no cover, the default cover, or the media's own artwork; the card's main row keeps its 62-DIP height in all three, so the flyout does not jump. The head shows an 18-DIP app icon before the name when the shell can render one for the session's AUMID; the session-switch arrow sits on a 20-DIP button; an app without an icon shows the name alone. The 正在播放 settings page controls the card: the display switch, the playback controls, the cover colors, and the audio level. The display switch hides the card (and shrinks the flyout); the preview and the option rows stay active. The receiver track info is not a setting: the app pushes the title, artist, album, and cover whenever a session streams, and the card's display master does not gate it. The playback head's ALAC line carries the active receiver's effective latency: the global base plus that row's DSP/DAC delay, clamped to 20–4000 ms, e.g. `ALAC · 44.1 kHz · PTP · 已同步 · 延迟 700 ms`. An idle engine shows the base. While a latency change restarts the session, the flyout holds the last streaming snapshot for up to 3 s, so the device row, footer, and tray keep their streaming face; a spinner follows the 播放 label, so the right-aligned ALAC line never shifts. Preset clicks coalesce for 300 ms and custom edits for 500 ms before that restart, so rapid switching sends one restart with the final mode; the hold starts at the restart, not at the first click. An error, the timeout, or a user disconnect returns the real connecting state.
- The settings window's page area is 720×500 (min 640×420) with the system title bar hidden; a custom bar draws under the system window buttons (`settingsTitleBar`), and a 190-wide sidebar switches nine pages: 通用, 连接, 接收器, 音频, 氛围灯, 采集, 正在播放, 更新, 关于. One content column carries the title, cards, and notes: it caps at 720 DIP and centers on a wider window, so rows keep their rhythm instead of stretching, while the overlay scrollbar stays at the window edge. The 正在播放 page is one card: the 媒体卡片 title with the 托盘面板中显示 chip and the display switch, a preview of the real media card — the live session when present, otherwise a sample card so the preview never disappears (the preview is read-only and stays live; the display switch only hides the flyout card), a 封面 row whose three-way segmented control sits at its right (无 / 默认 / 媒体), then rows 播放控制, 封面配色, and 音频电平; the receiver track info is always pushed and has no row. Its copy uses 媒体卡片 / 托盘面板中显示 / 播放控制 / 音频电平 / 封面配色. The 音频 page's latency mode card has three preset tiles (低延迟 200 ms, 标准 1.5 s, 稳定 2 s) and a custom tile whose slider expands only while custom is selected; below 714 DIP the three presets stack as full-width rows in the custom tile's shape; at or above it the three cards share one row height, the tallest description's, so a description that wraps to another line grows the whole row instead of leaving its card uneven with the others, and no name, value, or description leaves its card; its header chip 托盘面板中显示 sits beside the toggle that shows or hides the flyout's four-segment row. Each page body scrolls inside the fixed title area when the window is shorter than its content, so the 420 DIP minimum still reaches the custom slider and the read-only rows. The title block ends in a divider; the overlay scrollbar runs in the 20 DIP gutter at the window edge, clear of the cards, and the audio page's read-only rows use the shared `settingRow`. The 连接 page has two sections above its switches card. 已连接设备 labels a card that lists every target in the session: a 24-DIP glyph, the device's name, a second line of model · channel · volume, and the member's state (正在播放, 正在连接…, 正在重连…, 连接失败) right-aligned and vertically centered; a retransmit share of at least 0.5% or any underrun joins that second line in the warning color, and healthy devices stay quiet. A member the engine dropped leaves the list and appears under the card as a notice row, {name} 已断开 with 重新连接, until the next user connect or disconnect. 本次连接 labels a card that appears only while the session streams and the engine has measurements: a 2×2 grid of 已连接时长, 稳定性 (良好 or 有卡顿, with 丢样 and 欠载 on the label line), 网络重传, and 重连, separated by one full-width hairline; the card carries no state chip and no advice row. Both section labels use the 11.5 / 600 / letter-spaced muted group style above the card, not the in-card tool header. The page states no settings and no device constants: the latency mode stays on 音频, and the receiver's own processing time has no surface. The settings sidebar's identity names a multi-member session by its first member and a count (「HomePods 和其他 1 台」, 「HomePod R and 3 more」) — the joined name overflows the 190-DIP sidebar — and carries the joined session name as the row's tooltip; one member keeps its own name, and a stereo pair reads 已连接 · 立体声组. Below the card are the three session switches: 断开后自动重连, 严格验证接收器, and 连接后静音本机输出. The mute switch is on by default; its subtitle follows the engine's mute state (off, waiting for a connection, muted now, or failed), and the driver caveat appears under the card only while the switch is on.
- The 通用 page carries the sender name with its 保存 field commit, 登录时自动启动, 托盘动画, and the 语言 and 外观 selects, which follow the system by default; a caveat under the card names the mute switch's capture side effect. The 采集 page carries the capture endpoint and, on macOS, the per-app selection with app icons and its own local-mute option; Windows offers the loopback endpoint alone.
- The 接收器 page is the receiver-management surface: a merged list card (remembered, manual, and stereo groups in one card) under the 已启用 group head with its count pill — the head and pill render only when the list has rows — a dashed 添加接收器 row with an accent plus tile and a one-line hint below the card, and a collapsible 已隐藏 group (same card background, greying the row's name, glyph, and expanded settings) under a divider below the add row. Both the flyout and this page show manual receivers and discovered receivers that are online; an offline discovered receiver is not listed, and its saved settings return when it is seen again. The active session's row stays even when it just went offline. An empty page is plain prose where the list would be, with no border or icon: no receivers at all shows 暂无接收器 over the discovery line (网络上的 AirPlay 接收器会自动出现在这里。), every receiver hidden shows 所有接收器都已隐藏 at 12.5 px over the existing recovery hint, and the add row follows in both cases, then the hidden group. A receiver row expands in place: the head carries the glyph with the online dot, the name line with 手动添加 / 启动时 / 已隐藏 chips and the model-or-address subtitle, an 编辑 side button on expanded manual rows, the row-tail enable switch (on = shown in the flyout, off = moved to the hidden group), and a rotating chevron. The edit button overlays the gap before the tail, so every row's switch keeps one x. The expanded body is full width, no inset panel: 启动时自动连接 (multi-select — every flagged receiver connects at launch as one cohort; 可勾选多台；启动时会一起连接), the 音量 row (the percent on its title line, the slider beneath) and the 声道 row, each a settings row carrying the page's title size with the same hairline between them (立体声 / 左 / 右 for a single receiver, or a disabled 立体声 on a pair; the per-device delay slider was removed from settings at the user's request), and the 接收器密码 row only when the receiver can use one (a Mac, a manual row, or any row with a saved password; a PIN-paired HomePod or Apple TV hides it unless a password is saved), with a masked •••••• pill when saved and a key-icon 更改/设置 text button. Three dialogs open over the window with the shared `dialogScrim`: add/edit (name + type, host, port with its default following the type, password authentication select with a conditional password field, and a red 移除接收器 in the edit footer), password (a masked 新密码, the local-only hint, 清除已保存密码), and remove (red head, two hint lines, red 移除 commit). Every dialog keeps a reserved error row so its footer never jumps, and the footer buttons are the shared 34-DIP pills. A receiver on the machine running saundo is not a target: it appears only in the 已隐藏 group, with a 本机 chip, no enable switch, no chevron, and no expandable body, and the flyout never lists it. The engine refuses any connect to it, including a manual row and a remembered last device.
- A stereo combo (软件立体声组合) is user-created configuration over two independent AirPlay 2 receivers, rendered under the 接收器 page's own 立体声组合 section — the same group-head style as 已启用 with its count pill — so the combo's long expanded body never runs into a single receiver's card. The combo row carries the stereo glyph, the name with the 立体声组合 chip, and the member names joined with 「 + 」 as the subtitle — a combo named with the derived default already carries both names, so its subtitle names the two models instead (identical models read once) and the name and subtitle never repeat one string; while expanded the tail places 解除组合 beside the enable switch (the combo section owns its card, so the switch's x may move here). The expanded body holds 启动时自动连接, the 声道布局 map as a block row: the title keeps its own line above two borderless pill half-cards whose centered muted side labels (左, 右) sit over each member's dot and name, the offline half turns dashed with its row dimmed to 45%, and a quiet ghost swap button between them flips the sides in place; the engine hot-applies the new sides without a rebuild — a warning bar naming the offline member (「{name}」未连接，无法启动组合) when one side is down, and one 音量 row for both members. 组成立体声组合 opens the create dialog below the two dashed add rows: the sides are two plain form fields (左声道, 右声道) whose selects carry the 选择接收器… empty state, with one muted line noting that only AirPlay 2 receivers are listed, the name follows with the derived 「A + B」 suggestion as its placeholder, and 组合 commits at 40% opacity until both sides are chosen. Unlinking opens a red-headed confirm dialog (解除立体声组合) that names what splits and that each receiver keeps its own settings. A combo's members drop from the receiver list and the flyout while the combo exists; the combo row stands in for them with one volume and no channel control, carries the 立体声组合 tag beside its name on both the plain and the mixer layout (the flyout's channel button is disabled with the 立体声组合 · 左 + 右（已锁定） tooltip), and its plain row's second line names the two sides (the models when the name already carries them). Linking a receiver that plays ends that session first, and removing a receiver unlinks any combo that held it.
- The 氛围灯 page and the flyout's ambient card are one global choice, not per device. The card is permanent: its head carries the label and a power action (关闭氛围灯 when lit, 开启氛围灯 when dark); the settings card head adds the desk-lamp glyph. Off sends the paused playback state and turns the top display dark without removing the card. The settings page mirrors it with a 72-DIP preview of what the top display follows and its localized name, then a 颜色来源 row (封面 / 模板) whose segment sits at its right, then a 模板 block (六组预设灯光颜色) whose six fixed 68-DIP templates 暖烬, 沙丘, 苔庭, 潮汐, 兰夜, 月白 wrap under it on a narrow page; its head keeps the HomePod 专属 tag. The preview follows the media cover through the same Lab k-means the receiver uses for its MediaColors, rendered as a three-color glow; it reads the session the app pushes to the receiver (the system's current session), not the media card's arrow selection, so the preview and the top display cannot disagree. With no cover yet it shows a neutral cover tile with the media glyph. The receiver's own fresh-session placeholder is a white center on a dark ring, but the app preview does not mimic it. A template tile paints the template's three-color glow; its carrier JPEG is three flat color fields that the receiver's k-means reduces back to those colors. The flyout uses the compact segment in the row, left of the chevron, and the same six swatches; with 封面 chosen the row shows the preview, the current source and the segment, with no chevron and no template list, and with 模板 chosen the chevron appears with the swatches collapsed until it is clicked. Picking a template switches to 模板 and leaves the flyout list open; choosing either segment turns the light on. Hiding the flyout folds the list, so the next open starts collapsed. When the light is off, the preview dims to 35% like the templates, the name and a 已关灯 chip mark the state, the priority segment and the templates disable, and only the power action works; the flyout row keeps the preview, name, chip and disabled segment with no chevron or list. Turning the light on restores the current choice and leaves the template list collapsed. The chevron rotates 160 ms. Both surfaces read the same `Snapshot.LampOff`/`LampCover`/`LampPreset`; the tray menu's ambient row reads that snapshot too. A fresh session with no cover shows the device placeholder; after a template or cover has been sent, clearing the artwork keeps the last light, because the sender has no clear-artwork command. Below the templates sits one 自动关闭氛围灯 row: a 150×28 select with 从不, 1, 5, 10, and 30 分钟, default 30. The engine turns the top display off after that long without playback and lights it again on the first audible sample. While it holds the display dark, the flyout lamp card carries a 待机 chip, its power action reads 开启氛围灯, and the footer reads 已待机 · 播放声音即唤醒; a manual light action holds the light on until the next sound.

"更新内容" opens a read-only dialog over the settings window (`update_dialog.go`) with the shared `dialogScrim` behind it. Its head uses the shared `dialogHead`, with the range select in the head's trailing slot. It lists every version released since this build from the repository's localized changelog, `CHANGELOG.md` or `CHANGELOG.zh-CN.md`, chosen from the app language (`i18n.Locale`), over raw.githubusercontent (`update_history.go`): the offered version opens in full and the older ones follow as folded rows with their date and a count. The fetch starts when the update is found, so the dialog usually opens with the localized entry in place. Until it lands, a non-English dialog shows the loading row instead of flashing the manifest's English notes; the fetched entry replaces them, and the manifest stays the fallback when the fetch fails. A range field switches between that list and the latest version only. Notes render with `ui/markdown.View` under a dialog-sized theme, and version numbers use tabular figures. A found update also shows as the flyout chip and the tray tooltip; no window opens on its own.
- The settings 更新 page repeats the same state in an S1 card above its rows, and the flyout footer carries an update chip that opens that page. All three read one update state; installing from any of them shows the same progress, with `mygo.Updater` doing the signed download and install.
- All windows read the same App state; an engine snapshot update redraws them.
- The flyout root paints the panel surface explicitly, because a flyout is transparent by default.

## State faces

- One smile mark carries the product. The tray icon and the flyout footer show the face whose mouth names the phase: `idle-open` (open eyes, straight line) while disconnected, `smile` while the session is connected but silent, `stream` (spectrum bars) while streaming, `connect` (three dots) while connecting or reconnecting, `error` (X eyes) on failure. A connected stream with no audible audio shows `smile`: after five seconds of digital silence the engine suspends RTP and reports `Snapshot.AudioIdle`, so the face names playback, not the session. The empty device card pulses the search face while discovery runs.
- A session taken over by another sender keeps the error phase and uses the copy 已被其他设备接管 / Taken over by another device, with 重新连接 / Reconnect as the active row's action. The tray keeps the error face. A user connect or disconnect returns the idle face.
- While streaming, the other online receiver rows keep their 连接 / Connect action: choosing one adds that receiver to the cohort, and the local-output mute stays in force across the rebuild. While a connection attempt is in progress, the other rows stay disabled until it finishes or is cancelled.
- The tray animates the `stream` and `connect` faces at 12 frames per 100 ms while the 托盘动画 setting is on. Turning the setting off, or Windows animation effects (Reduce Motion), holds the static face. The static stream icon is animation frame 0; the static connect icon is a fixed three-dot face, and the animated connect frames pulse the dots.
- The 32 px tray icon is monochrome — black on a light taskbar, white on a dark one — and redraws on `Tray.OnAppearanceChange`. The tooltip carries the finer session state. The tray menu lists one row per visible receiver in snapshot order, up to six, each with its receiver-family glyph; every in-session receiver draws its glyph in the accent color (`#4f46e5` light, `#a5b4fc` dark) and is disabled, other rows use the menu template, and an offline row carries 离线 and stays clickable. A row click connects or adds that receiver to the session; while connecting every row is disabled. The session action row under the list reads 取消连接, 断开连接, or 重试连接 and is absent while idle. The playback group follows when the system media session has controls: 上一首, 暂停 or 播放, and 下一首; the menu shows no track title. It is absent when playback controls are off or no controllable session exists. The ambient-light submenu row follows with its current source as subtitle — 已关灯 when off, otherwise 封面 or the template name — and its submenu holds the 关闭氛围灯 / 开启氛围灯 power row, a 封面 choice, and six template choices, each with a round color preview; the choices are disabled while the light is off; the power row turns the light on, then a choice can be picked, matching the flyout and settings. No row uses a check column; the current choice is disabled while lit and its label ends in a single-color ✔, and every choice is disabled while off, where the stored choice carries 上次. While the light is on, the ambient parent row's icon is the current cover or template preview; off uses the lamp-off glyph. Then 显示托盘面板, 设置…, a stateful update row (下载更新 {version}, 正在下载 {percent}%, 重启并安装 {version}) only while an update waits, and 退出声渡. More than six receivers add 更多接收器… opening the receivers page; no visible receiver shows 重新搜索 with 暂无接收器 first. The menu is installed only for the popup and is rebuilt on right click.
- Device rows pick their filled glyph by receiver family, Mac form, and stereo pair (`TestDeviceIconFollowsModel`). A stereo group with both member devices present keys its pair glyph off the members' own models, never the row's — two minis pair at mini size, two full HomePods pair at full size, a mini beside a full HomePod takes the combo glyph, and a pair with a non-HomePod member takes the generic two-speaker glyph — so swapping a combo's sides cannot change its icon (`TestStereoIconFollowsMembers`).
